# 🔎 Chapter 03: Mapping the Digital Footprint

This chapter builds on the information discovered during Chapters 01 and 02 and expands the investigation from individual identifiers into the broader digital footprint of a website, domain, organization, and its associated infrastructure.

Starting with a domain discovered during the earlier investigation, we use Linux based reconnaissance and OSINT tools to discover URLs, crawl websites, capture screenshots, mirror web content, generate reports, investigate geographic information, and research businesses and organizations.

The goal is to demonstrate how a single domain can become the starting point for a much larger OSINT investigation.

# 🌐 Part 1: Starting With the Domain

The previous chapters gave us several pieces of information that can be used as breadcrumbs.

Now we take one of those breadcrumbs and expand the investigation.

For this chapter, the starting point is a website:

```text
https://freshforensics.tech
```

Instead of looking at the homepage and stopping there, we want to discover what else exists within the website.

Our first goal is to identify additional URLs and endpoints.

---

# 🕷️ Part 2: Discovering URLs With Katana

[Katana](https://github.com/projectdiscovery/katana) is a fast web crawler from ProjectDiscovery that can be used to discover URLs associated with a target.

The Linux binary used during the livestream was version `1.7.0`.

### 📥 Download Katana

Katana releases are available here:

```text
https://github.com/projectdiscovery/katana/releases/tag/v1.7.0
```

After downloading the Linux binary, make it executable if necessary:

```bash
chmod +x katana
```

### 🔎 Crawl the Website

Run Katana against the target domain:

```bash
./katana -u https://freshforensics.tech -d 3 -silent -o urls.txt
```

The discovered URLs are written to:

```text
urls.txt
```

We can examine the results:

```bash
cat urls.txt
```

The URL list may contain multiple paths and resources that are not immediately visible from the homepage.

---

# 🧹 Part 3: Cleaning the URL List

Reconnaissance tools can sometimes return duplicate URLs.

We can remove duplicates with:

```bash
sort -u urls.txt -o urls.txt
```

Now the file contains a unique list of discovered URLs.

```bash
cat urls.txt
```

This file becomes an important piece of the workflow because we can pass the discovered URLs into other tools.

---

# 👁️ Part 4: Visual Reconnaissance With EyeWitness

Once we have a list of URLs, we can use EyeWitness to capture screenshots of the discovered web pages.

EyeWitness is useful because a large URL list can be difficult to examine manually.

Instead of opening every URL individually, we can generate a visual report.

### 📥 Download EyeWitness

Clone the repository:

```bash
git clone https://github.com/RedSiege/EyeWitness.git
```

Enter the setup directory:

```bash
cd EyeWitness/setup
```

Run the installation script:

```bash
./setup.sh
```

Return to the EyeWitness directory:

```bash
cd ..
```

Activate the EyeWitness environment:

```bash
source eyewitness-venv/bin/activate
```

---

# 📸 Part 5: Using EyeWitness

EyeWitness can be used against individual URLs or lists of URLs.

### 🌐 Scan a Single Website

```bash
python Python/EyeWitness.py --single https://example.com
```

### 📄 Scan a List of URLs

We can use the URL list generated by Katana:

```bash
python Python/EyeWitness.py -f urls.txt
```

This creates a visual report containing screenshots of the discovered pages.

### 🗺️ Using Nmap Results

EyeWitness can also process Nmap XML output:

```bash
python Python/EyeWitness.py -x nmap_scan.xml
```

### 📁 Specify an Output Directory

We can specify where the report should be stored:

```bash
python Python/EyeWitness.py -f urls.txt -d /path/to/output
```

# 🔗 Part 6: Connecting Katana and EyeWitness

This is where the workflow becomes more interesting.

Instead of treating the tools as separate utilities, we can chain them together.

Katana discovers the URLs:

```text
Website
   │
   ▼
Katana
   │
   ▼
urls.txt
```

EyeWitness then processes those URLs:

```text
urls.txt
   │
   ▼
EyeWitness
   │
   ▼
Screenshots
   │
   ▼
Visual Report
```

We can also perform this workflow directly:

```bash
python Python/EyeWitness.py -f urls.txt -d eyewitness-report --headless
```

The result is a visual overview of the pages discovered during the crawl.

# 🕸️ Part 7: Crawling With wget

Katana is not the only way to discover URLs.

Linux also provides tools that can be used to crawl websites.

One example is `wget`.

We can use its spider functionality to crawl the target without downloading the pages:

```bash
wget \
  --spider \
  --recursive \
  --no-verbose \
  --level=3 \
  https://freshforensics.tech 2>&1 |
grep '^--' |
awk '{print $3}' |
sort -u
```

The output is filtered so that we are left with unique URLs discovered during the crawl.

This gives us another perspective on the structure of the website.

# 📥 Part 9: Mirroring a Website With HTTrack

Another approach is to create a local copy of a website.

HTTrack can download website content and recreate the site's structure locally.

Install HTTrack:

```bash
apt install httrack
```

Mirror the website:

```bash
httrack https://freshforensics.tech -O ./fresh-forensics
```

The downloaded website will be stored in:

```text
./fresh-forensics
```

Enter the directory:

```bash
cd fresh-forensics
```

We can then use Python's built in HTTP server to make the local copy accessible through a browser:

```bash
python3 -m http.server 8888
```

Open:

```text
http://0.0.0.0:8888/
```

This allows us to examine the downloaded website locally.

# 🧪 Part 10: Generating Reports With Carbon14

[Carbon14](https://github.com/Lazza/Carbon14) provides another way to generate information from a website.

We create a dedicated Python environment:

```bash
python3 -m venv carbon14Environment
```

Activate it:

```bash
source carbon14Environment/bin/activate
```

Install Carbon14:

```bash
pip install carbon14
```

Run Carbon14 against a target:

```bash
carbon14 https://example.com > report.md
```

The output is redirected into:

```text
report.md
```

This gives us a report that can be saved, reviewed, searched, and incorporated into the larger investigation.

# 🌎 Part 11: Geographic OSINT With Google Earth

Some investigations eventually produce geographic information.

Coordinates, addresses, locations, businesses, photographs, and other geographic clues can become additional breadcrumbs.

Google Earth provides a way to visualize geographic information discovered during an investigation.

### 📥 Download Google Earth

Download the Debian package:

```bash
wget http://dl.google.com/dl/earth/client/current/google-earth-stable_current_amd64.deb
```

Install it:

```bash
apt install -y ./google-earth-stable_current_amd64.deb
```

Remove the downloaded package after installation:

```bash
rm google-earth-stable_current_amd64.deb
```

Geographic information discovered during the OSINT process can then be examined within Google Earth.

# 🧠 Part 14: The Fresh Forensics Method

The objective is not simply to run every OSINT tool available.

The objective is to understand how the information connects.

In Chapter 02, a publicly accessible Google document became the starting point for discovering an owner, email address, and Google identifiers before moving into GHunt. Pasted text

Chapter 03 takes that same philosophy and applies it to websites.

We start with a domain.

The domain produces URLs.

The URLs produce screenshots.

The website can be mirrored locally.

Reports can be generated.

Geographic information can be investigated.

Business information can be researched.

The investigation becomes a process of following the breadcrumbs rather than simply collecting tool output.
